用 Agent 驱动的
短剧生产工作台

AIComicBuilder 不是底层视频模型，也不是万能 Agent。它控制整个生产流程，在关键节点指挥 Agent 和生成模型执行任务，持续保存结果、推进审核与返工，最终实现目标短剧视频。

输入：创意、小说改编稿、剧本控制：任务队列 + 状态 + 资产版本执行：Agent + 图像/视频模型输出：逐镜视频 + FFmpeg 成片

谁在驱动谁？

基础模式下，AIComicBuilder 是流程控制者，Agent 是可插拔的智能执行节点。Agent 返回结构化结果后，工作台写入数据库并决定进入下一步还是返工。

01 / CONTROL

AIComicBuilder

决定当前工序、准备上下文、创建任务、保存版本、展示审核状态。

02 / REASON

我们的 Agent

完成小说改编、角色分析、导演分镜、提示词和质量判断。

03 / GENERATE

生成模型

OpenAI、Gemini、Kling、Seedance、Veo、Wan 等生成文字、图片和视频。

04 / DELIVER

目标视频

逐镜结果经字幕、转场、BGM、片头片尾和 FFmpeg 合成为短剧。

它如何推进工作

按钮或“一键续跑”只是入口，真正的核心是任务状态和可重复执行的生产节点。

输入小说改编稿或剧本小说需要先完成章节选择、压缩、分集和剧本化。
创建待执行任务任务记录类型、项目、分集、输入、状态、重试和错误。
调用 Agent 或模型可使用内置提示词，也可按类别绑定百炼、Dify、Coze Agent。
写入结构化结果保存角色、关系、场景、分镜、对白、动作和资产版本。
审核、返修、继续失败镜头可单独重做，已有项目状态和上游资产不会丢失。
逐镜生成并合片首尾帧或参考图驱动视频模型，最后由 FFmpeg 输出成片。

什么时候有意义

它的价值不是让单次生成更快，而是让长期的 Agent 生产过程可见、可控、可审核、可返工。

适合采用

  • 小说漫改、连续短剧、多集生产
  • 角色和场景需要跨镜头保持一致
  • 需要版本、审核、失败重试和逐镜返修
  • 多个 Agent 与多家模型需要统一上下文

不必采用

  • 只做一次性样片或单条短视频
  • 现有 Agent 脚本已能完成简单闭环
  • 已经拥有成熟任务编排、资产库和审核后台
  • 尚未决定进入短剧生产业务
本地验证：原创概念样例已走通剧本、角色、场景、3 个分镜和 6 张首尾帧；未配置付费视频模型，因此未将静态关键帧冒充成 AI 视频。
Final decision

现在归档，需要做短剧时再启用。

重新启动研究的条件：我们正式进入小说短剧生产，并且单次 Agent 流程已经出现多集、角色一致性、版本和返修管理瓶颈。届时首先验证小说改编 Agent、TTS/口型、严格质检和成本路由。
