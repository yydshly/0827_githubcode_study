核心判断

模型负责生成，提示词负责表达，仓库负责让成功经验可被发现和复用。

研究重点应放在前两者；外围平台只在真实规模问题出现后建设。

Architecture / 双层架构

不要把模型能力和仓库能力混在一起

上层解决“能生成什么”，下层解决“如何把有效经验持续沉淀”。两层结合才形成完整价值。

A

Gemini 3 Pro Image

图像生成能力层

接受文本与参考图，经过多模态理解和推理，生成、编辑或迭代视觉结果。

  1. 输入理解文字、单图、多图、现实知识
  2. 视觉规划主体、构图、镜头、布局
  3. 图像合成材质、光线、文字、一致性
  4. 编辑迭代局部修改、多轮收敛、适配平台
B

Awesome Prompt Repository

提示词资产系统层

把社区中零散的成功案例变成可搜索、可比较、带出处并能持续更新的内容资产。

  1. 收集社区案例与结构化投稿
  2. 审核质量、来源、安全与格式
  3. 组织分类、精选、变量和多语言
  4. 分发CMS、README、网页图库与一键尝试

Prompt Anatomy / 提示词结构

有效提示词不是更长，而是约束更清楚

点击结构层查看它解决的问题。真正可复用的是这种表达结构，而不是机械复制整段文字。

Value / 对当前项目的价值

现在拿走方法，后续再建设平台

研究阶段的目标是缩短试错并形成最小工作流，而不是先承担一个内容平台的维护成本。

NOW / 当前高价值

理解与验证

  • 能力地图快速判断 Gemini 适合承担哪些视觉任务。
  • 案例先验从成熟构图出发，减少从零试错。
  • 参数模板把主体、风格、参考图和约束变成可替换字段。
  • 小样本评测用 10–12 条案例识别优势、失败与成本。

LATER / 需求出现后

规模化与平台化

  • 数据库与检索模板超过人工可维护规模后再建设。
  • 投稿与审核出现稳定的团队或外部贡献后再建设。
  • 多语言产品明确面向不同语言用户后再投入。
  • 自动推荐人工模板流程验证有效后再引入 RAG 或 Agent。
NEXT

第一轮研究的停止条件

选取 10–12 条提示词做小样本测试，能够沉淀 3–5 个稳定模板，并能回答“下一步最小生图工作流是什么”后即停止，不继续整理全库。

Boundary / 使用边界

案例是能力证据，不是效果承诺

  • 相同提示词在不同模型版本、平台参数和参考图下可能产生不同结果。
  • 信息图、地图、医疗、金融等事实性内容必须进行独立核验。
  • 示例图片、人物、品牌和商标的商业使用权需要分别确认。
  • 仓库许可不自动替代第三方内容的作者归属与授权判断。
