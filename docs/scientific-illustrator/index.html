05 / Mechanism

原理不是“更长的提示词”

真正的工程价值来自设计规格、受控工具、双证据审计和最小修正之间的闭环。

01

视觉理解

Codex 识别面板、阅读顺序、文字、图元、拓扑、颜色和不可约图片区域。

reconstruction_spec
02

能力探测

先询问当前 backend 支持的原生对象和可编辑复合对象，避免虚构能力。

*_get_capabilities
03

对象构建

按区域、从后到前创建稳定 ID 对象；用户可以看到或按检查点审阅进度。

add / group / align
04

双证据审计

结构审计检查几何与可编辑性，渲染证据检查视觉、文字和连线路径。

audit + screenshot
05

对象级修正

只移动、替换或重画导致问题的最小对象，不用大截图掩盖缺陷。

correction_plan
06 / Product fit

什么时候值得用

强适配
⌁

机制图与通路图

节点、箭头、分区和标签具有清晰语义，最适合恢复为原生图元。

强适配
⇢

实验与方法流程

步骤明确、重复构件多，适合模板化、对齐和批量样式统一。

强适配
▦

基金与汇报插图

需要持续改字、改配色、改版式，可编辑源文件的价值明显。

条件适配
⌗

多面板实验结果

框架和标注可以重建，但显微照片、热图等仍需原子图片对象。

条件适配
⌇

常规数据图表

柱、线、散点等可以重建；复杂统计图更适合数据驱动绘图库。

弱适配
✦

照片级与艺术插画

像素级纹理、3D 渲染和强艺术风格不是 draw.io/PPT 图元的优势。

09 / Try it

真实使用时，提示词应该强调“可编辑”和“逐区域检查”

使用 Scientific Illustrator，在 draw.io 中复刻我上传的科研图。优先使用可编辑的文字、图形、连接线、表格、图表和分组对象；只把无法可靠绘制的最小区域保留为图片。按区域逐步绘制并检查结构和截图，修正后保存 .drawio，再导出 2000 px PNG 预览。

上方已真实运行无需桌面应用的 drawio-file-utils 模式；若要演示实时画布、截图和导出，还需要安装 draw.io Desktop。PowerPoint/WPS 实时模式同样需要对应宿主。
