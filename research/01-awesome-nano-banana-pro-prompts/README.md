## 1. 研究定位

该仓库不是图像生成模型，也不是一套完整的生图应用源码。

它的核心是一个主要面向 Google `Nano Banana Pro / Gemini 3 Pro Image` 的社区提示词案例库，围绕提示词保存了描述、示例图片、作者、来源、语言和分类；同时提供了一套轻量的投稿、审核、CMS 同步和多语言 README 发布流程。

我们研究它的主要目的：

1. 理解当前 Gemini 生图的能力大方向。
2. 理解高质量生图提示词通常由哪些部分组成。
3. 找到可以快速复用和验证的提示词模式。
4. 为以后建设内部提示词模板、Skill 或视觉生产工作流留下参考。

本阶段不以复刻网站、数据库或社区系统为目标。

## 2. 一句话结论

当前最值得研究的是“模型能力地图 + 提示词结构 + 生成迭代方式”；数据库、投稿审核、多语言、社区运营和自动发布只需要知道其作用，等项目产生真实需求后再实现。

## 3. 仓库宏观架构

```text
社区案例 / 用户投稿
        ↓
GitHub Issue 结构化表单
        ↓
人工审核并添加 approved 标签
        ↓
GitHub Actions 解析内容和图片
        ↓
写入 YouMind CMS
        ↓
分类、排序、精选和本地化
        ↓
每四小时生成多语言 README
        ↓
GitHub 案例库 / YouMind 网页图库
        ↓
用户复制、修改提示词并调用生图模型
```

这里有两个需要明确区分的系统：

- **提示词资产系统**：仓库和 CMS 负责收集、组织、展示与分发案例。
- **图像生成系统**：真正理解提示词并生成图片的是 Gemini 图像模型，不在该仓库中。

## 4. 提示词能力地图

以下是本项目当前需要理解的大方向，不要求逐条研究仓库中的全部提示词。

### 4.1 基础生成能力

- 文本生成图片：根据自然语言生成新的视觉素材。
- 图片辅助生成：结合人物、产品、服装、Logo、姿势或风格参考图生成。
- 多参考图组合：把多个独立元素融合到同一场景。
- 多轮迭代：在已有结果上继续修改，而不是每次从零生成。
- 局部编辑：替换、增加、删除或调整指定区域，尽量保持其他内容不变。

### 4.2 视觉控制能力

- 主体：人物、角色、商品、动物、建筑、车辆、食物等。
- 场景：室内、自然、城市、幻想空间、商业摄影棚等。
- 构图：近景、全景、俯拍、低角度、对称、不对称、网格布局等。
- 镜头：景别、焦距、景深、焦点位置和摄影机角度。
- 光线：自然光、棚拍光、逆光、轮廓光、夜景和电影化照明。
- 色彩：品牌色、限定色板、冷暖关系、饱和度和色彩分级。
- 风格：摄影、电影、插画、动漫、3D、像素、版画、水彩、水墨等。
- 输出规格：横竖比例、平台尺寸、清晰度及 2K/4K 等要求。

### 4.3 专业资产能力

- 图中文字与排版：海报、标题、标签、包装和信息卡片。
- 产品营销：商品主图、广告场景、包装概念、品牌视觉。
- 人物与角色一致性：在多个场景中尽量保持身份、服装和特征。
- 信息图和知识图：把流程、步骤、知识点或数据组织为视觉内容。
- 分镜和漫画：按镜头或面板组织连续叙事。
- UI 与概念设计：生成网页、App、游戏界面或视觉方向稿。
- 多语言视觉：在图片中生成或替换不同语言的文案。

### 4.4 仓库案例的主要应用方向

可以把仓库中的大量分类压缩为六个研究方向：

1. **个人与角色**：头像、人物摄影、角色设定、多人合成。
2. **营销与电商**：产品图、广告、包装、社交媒体、视频封面。
3. **知识可视化**：信息图、流程图、教育插画、地图和图表。
4. **叙事内容**：漫画、分镜、电影概念、连续场景。
5. **数字产品与游戏**：UI 概念、图标、场景、角色和道具素材。
6. **艺术与风格探索**：摄影、插画、3D、复古、像素、东方艺术等。

## 5. 高质量提示词的通用结构

提示词的价值不只是“写得长”，而是将模糊意图拆成可执行约束。

```text
1. 目标与用途
   要生成什么资产，给谁使用，最终出现在哪个平台。

2. 输入与参考
   有哪些参考图，各自代表人物、产品、服装、姿势还是风格。

3. 主体与场景
   谁或什么是主体，在哪里，正在做什么。

4. 构图与镜头
   画幅、景别、视角、主体位置、空间关系和焦点。

5. 风格与质感
   摄影、插画、3D 或其他风格，以及材质和画面气质。

6. 光线与色彩
   光源方向、时间、氛围、主色和品牌色。

7. 文字与布局
   图片中需要出现的准确文字、字号层级、位置和排版结构。

8. 保留项和禁止项
   哪些内容必须保持一致，哪些内容不能增加或改变。

9. 输出要求
   比例、分辨率、背景、文件用途和最终数量。

10. 迭代指令
    下一轮只修改什么，其他部分保持不变。
```

### 可直接复用的最小模板

```text
目标：为【使用场景】生成一张【资产类型】。

参考输入：使用参考图 A 保持【人物/产品】特征；参考图 B 仅参考【风格/服装/构图】。

主体与动作：【主体】在【场景】中进行【动作】。
构图与镜头：【画幅比例】、【景别】、【视角】、主体位于【位置】。
风格与质感：【视觉风格】、【材质/画面气质】。
光线与色彩：【光线】、【主色板】、【品牌色】。
文字与布局：准确显示“【文字】”，位于【位置】，采用【排版特征】。
必须保留：【身份、产品结构、Logo、颜色等】。
禁止出现：【不需要的元素或变化】。
输出：【比例/分辨率/数量】。
```

## 6. 生成效果为什么会改善

案例库能够减少试错，主要依靠以下机制：

- **案例先验**：先找到已经成功过的视觉组织方式，再替换业务变量。
- **需求结构化**：把“做得高级一些”拆解为构图、光线、材质和排版。
- **参考绑定**：明确每张参考图负责什么，降低错误融合。
- **约束显式化**：把必须保留和禁止修改的内容写出来。
- **局部迭代**：一次只改变少量因素，便于判断哪个调整真正有效。
- **结果沉淀**：记录提示词、模型、输入图、参数和结果，形成可重复模板。

提示词不会保证确定性结果。模型版本、随机性、参考图质量、内容复杂度和平台参数都会影响输出。

## 7. 当前阶段的最小研究方式

不要阅读全部提示词，也不要先搭建完整系统。第一轮只做小样本验证：

### 样本选择

从以下方向各选择 2 条代表性提示词，总量控制在 10～12 条：

- 产品或营销图
- 图中文字或信息图
- 人物/角色一致性
- 多参考图组合
- 分镜或叙事图
- UI、游戏或其他当前项目相关素材

### 每条提示词只观察七项

| 观察项 | 核心问题 |
|---|---|
| 任务类型 | 它解决什么视觉任务？ |
| 输入条件 | 是否需要参考图或外部信息？ |
| 提示词结构 | 使用了哪些结构模块？ |
| 关键约束 | 哪些描述最可能决定效果？ |
| 模型优势 | 它利用了 Gemini 的什么能力？ |
| 可迁移变量 | 哪些部分可替换为我们的内容？ |
| 实际结果 | 是否值得保存为内部模板？ |

### 第一轮产出

- 一张生图能力地图。
- 3～5 个经过实际验证的参数化提示词模板。
- 一份模型优势、限制和常见失败原因记录。
- 一个“是否值得进入当前工作流”的判断。

### 停止条件

能够回答下面四个问题后，就结束第一轮研究：

1. Gemini 生图最适合解决哪些任务？
2. 哪些提示词结构对结果影响最大？
3. 哪些模板与当前项目直接相关？
4. 下一步最小可实现的生图工作流是什么？

## 8. 非核心部分：只做描述，不深入

### 数据库与 CMS

作用：保存提示词、图片、作者、来源、语言、分类和精选状态。

当前不做。只有模板数量明显增加、多人需要共享，或文件方式已经难以维护时再考虑。

### 投稿与审核

作用：让外部用户提交内容，通过人工审核控制质量和版权风险。

当前不做。只有出现稳定的外部投稿或团队协作需求时再建设。

### 多语言

作用：翻译界面、描述和提示词，将内容分发给不同地区用户。

当前不做。只有产品明确面向多语言用户时再投入。

### 搜索、分类与推荐

作用：在大规模提示词中快速找到适合的案例。

当前使用文件夹、Markdown 标签或简单 JSON 即可。只有模板数量达到人工难以快速查找的程度，再建设检索或推荐。

### 社区与运营

作用：持续获得新内容、作者传播和搜索流量，形成内容增长循环。

这属于产品增长能力，不是当前技术探索重点。

### 自动设计提示词

作用：根据用户目标自动检索案例、选择模板并填写变量。

当前先人工总结稳定模板。只有人工流程验证有效后，再考虑用规则、RAG 或 Agent 自动生成。

## 10. 风险与边界

- 仓库数量很大，但数量不代表每条提示词都高质量。
- 同一提示词在不同模型、模型版本和调用平台上的效果可能不同。
- 社区提示词、示例图片、人物肖像、品牌和商标需要分别判断使用权。
- CC BY 4.0 的仓库许可不等于所有第三方素材都可以不经确认地商业使用。
- 信息图、地图、医疗、金融等事实性内容必须单独核验。
- 不应为了整理资料而整理资料；只有经过实际生成验证的模板才进入我们的资产库。
