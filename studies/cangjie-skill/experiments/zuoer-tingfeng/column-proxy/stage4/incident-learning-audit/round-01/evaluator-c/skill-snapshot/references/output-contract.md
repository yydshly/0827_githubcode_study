# 输出契约

运行完整审查、比较两个复盘版本或用户明确要求评分时读取本文件。

## 所有模式都必须先输出

1. `响应模式`：五种模式之一。
2. `适用性说明`：为什么选择该模式。
3. `当前事故状态`：已稳定、仍在进行或无法判断。
4. `禁止推断`：当前材料不能支持的结论。

## `full_review` 输出结构

### 1. 事故摘要与影响

只写有证据的用户、业务、数据影响以及持续时间；不确定的数字标记为未知。

### 2. 证据账本

分别列出事实、假设、未知和冲突，并为每一项注明来源或取证动作。

### 3. 用户影响时间线

| 时间 | 事件 | 当时观察 | 决策/动作 | 结果 | 证据 |
| --- | --- | --- | --- | --- | --- |

### 4. 因果阶梯

| 层级 | 因果候选 | 支持证据 | 证据强度 | 替代解释/证伪方式 |
| --- | --- | --- | --- | --- |

层级按实际证据选择：直接触发、故障机制、工程控制、流程协作、责任边界、目标与激励。不要机械凑满。

### 5. 四项反模式审查

| 反模式 | 是否存在 | 判断依据 | 需要怎样重写 |
| --- | --- | --- | --- |
| 归责替代治理 |  |  |  |
| 局部补丁 |  |  |  |
| 复杂度增殖 |  |  |  |
| 不可验收 |  |  |  |

### 6. 分层整改表

| 行动 | 改变的风险机制 | 负责人 | 优先级 | 截止时间 | 验收证据 | 失败/回滚条件 |
| --- | --- | --- | --- | --- | --- | --- |

不要替用户编造负责人和日期。未提供时写“待指定”，同时把它列为关闭前缺口。

### 7. 学习闭环

- 未决问题与取证责任人；
- 复查日期；
- 复发验证场景；
- 预期变化的指标、拦截结果、影响范围或响应时长；
- 可以关闭和不能关闭的行动项。

### 8. 结论

给出 `可接受 / 需补证据 / 需重写整改 / 尚未形成学习闭环` 之一，并说明最关键的下一步。结论评价复盘质量，不作人员责任认定。

## 其他模式

- `evidence_gap`：输出证据账本、按优先级排列的取证清单、可以安全保留的假设；不输出确定根因。
- `active_handoff`：输出当前风险、恢复目标、建议参与角色、待保存证据和进入复盘的客观条件；不展开长期整改。
- `adjacent_transfer`：说明哪些学习闭环元素可以迁移、哪些结论未经验证，并指出更合适的能力类型。
- `stop`：简要说明停止原因、已知事实、需要保全的证据和应参与的专业角色。

## 可选评分

只有用户要求评分或需要比较版本时，使用 100 分量表：

| 维度 | 权重 |
| --- | ---: |
| 阶段与路由 | 15 |
| 证据纪律 | 20 |
| 因果深度 | 25 |
| 整改可执行性 | 25 |
| 学习与风险边界 | 15 |

评分必须逐项给出证据。80 分是研究阶段的暂定合格线，不等同于事故已经关闭，也不代替 Stage 4 的独立行为测试。

## 交付前自检

- 是否把未知写成了事实？
- 是否把时间先后写成了因果？
- 是否把人、团队或工具当成根因终点？
- 是否说明了每项整改改变什么风险机制？
- 是否用更多审批或人工看守制造了新复杂度？
- 是否遗漏负责人、期限、验收证据或复发验证？
- 是否越权执行了任何外部动作？
