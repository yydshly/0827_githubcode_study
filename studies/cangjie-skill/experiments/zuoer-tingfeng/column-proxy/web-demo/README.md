一个零第三方运行依赖的静态 Web 演示。Revision 11 在库级入口上增加 Agent Skill 内容转化生态对照：先解释 Cangjie Skill 的 6 项能力、8 类输入、7 阶段流水线，再把 9 个同类库和相邻产品放入 6 层生产链；随后展示 5 个上游代表案例，并把《左耳听风》作为受控深度验证保留完整 Stage 0–5C 证据链。

~~~powershell
cd E:\0827_codex_project\studies\cangjie-skill\experiments\zuoer-tingfeng\column-proxy\web-demo
~~~

打开页面后按这条主路径阅读：

- `#library`：先看 6 项核心能力、8 类长内容来源、7 阶段产线、三方责任和适用性判断；
- `#ecosystem`：查看 6 层生态价值链，筛选 5 个直接同类和 4 个质量/标准/分发项目，并读取我们的五层组合建议；
- `#case-gallery`：按视频课程、资料/工件集、长期文档或我们的验证筛选 6 个代表案例；
- `#our-case`：理解为什么《左耳听风》只是一个受控深度案例，不等于库只支持书籍；
- `#capability-atlas`：查看该案例整理出的 4 项能力方向、输入输出合同与成熟度；
- `#stage5b`：完整体验首个正式 Skill 的 Cloudflare 公开事故审计。

当前只有“系统性故障学习审查”是 6 / 6 正式 Skill；“技术学习规划”“架构决策评审”“技术领导力诊断”为 1 / 6 候选能力。页面不会把候选方向冒充已经安装或通过独立验证的 Skill。

## 查看 Stage 5B 完整演练

打开页面的“最佳演示”区，可以操作 `incident-learning-audit` 的完整能力面：

- 案例是 Cloudflare 2019-07-02 WAF 全球中断，事实来自两份 Cloudflare 官方材料；
- 五种响应模式都可以通过鼠标或方向键切换，并同时展示允许和禁止输出；
- `full_review` 的四个前置项和八段输出可逐步导航；
- 证据账本可筛选事实、推断和未知；六条因果都有证据强度和证伪方式；
- 六项官方整改被补成行动合同，显式显示负责人、期限、验收、失败条件和关闭缺口；
- 最终评分为 86 / 100，结论是“尚未形成学习闭环”：原复盘证据和因果很强，但公开行动记录不足以证明全部关闭；
- 2020 后续文章只用于部分确认引擎迁移，不外推为其他行动已完成。

这是当前任务依照已安装 Skill 生成的确定性交互回放，不是网页内实时 Agent。它证明首个 Skill 已能完整处理一个真实公开事故案例，但不替代用户组织内部材料试点。

## 试用能力协议

打开页面的“试用能力”，选择示例或输入自己的问题，然后点击“运行协议演示”。系统先经过适用域门，再决定是否进入四种能力路线：

- 技术学习规划；
- 系统性故障学习审查；
- 架构决策评审；
- 技术领导力诊断。

适用域门有三种结果：

- **核心域**：问题同时命中能力路线与技术、工程或研发组织信号，完整展示输入缺口、4 条候选证据、交付物和质量边界；
- **相邻域**：只命中可迁移的方法信号，允许试跑方法框架，但醒目标记“方法迁移待验证”，不声称领域有效性；
- **域外**：金融、医疗、法律等当前候选能力不具备专业知识或责任边界的问题会停止路由，不展示伪证据，并建议切换到合适的专业来源。

点击任一核心域或相邻域证据可以查看来源详情。点击“测试域外边界”可直接体验停止状态；把问题改回技术故障、架构、学习或研发团队场景后，可以继续完整运行。

## 检查

~~~powershell
npm.cmd run check
npm.cmd run verify:browser
~~~

`check` 会校验库目录的 6 项能力、8 类来源、7 阶段、6 层生态、9 个同类项目、5 层推荐组合和 6 个案例，同时继续验证 Stage 5A–5C 合同。`verify:browser` 会运行三组既有 Chromium 回归并在库级专测中加入 Revision 11 生态链、筛选和组合建议。覆盖 1440 / 768 / 390、明暗主题、reduced-motion、键盘焦点、状态恢复和错误态，证据分别写入 `evidence/validation.json`、`evidence/showcase-validation.json` 与 `evidence/library-validation.json`。

## 边界

- 页面演示 Stage 0/1、一个 Stage 1.5 试点、一个 Stage 2 正式构造、该 Skill 的 Stage 4 合成闭环、Stage 5A 项目级安装和 Stage 5B 真实公开案例；其余 246 条候选没有执行全量 Stage 1.5。
- [Stage 5B Cloudflare 完整审计](../stage5/incident-learning-audit/PUBLIC_CASE_CLOUDFLARE_2019.md)
- 数据来自第三方专栏代理语料的转化结果，不打包原始 119 篇正文。
- 问题识别和结果结构是确定性的研究演示，不是假装连接了 AI 后端，也不会编造事实性结论。
- 适用域门只是一层可解释的本地规则，不替代正式领域评测；相邻域结果必须继续验证，域外问题不会被强行路由。
- 页面不需要网络字体、CDN、登录、数据库或真实接口。
- 页面已经回放项目级安装、真实 Codex 宿主冒烟与公开事故完整审计，但浏览器本身不运行实时 Agent。
- 首个 Skill 的完整公开案例演示已完成；完整 Stage 5 仍需用户组织内部效度、DIGEST、多 Skill 关系图与跨项目分发。
