# 真实事故接入模板

请先复制 `case-template.json`。本文件解释每一类输入为什么需要，以及哪些内容不得进入研究仓库。

## 1. 授权与脱敏

- 材料所有者是否明确允许用于本研究子项目；
- 是否已删除真实姓名、邮箱、电话、客户标识、内部域名和工单私密链接；
- 是否已删除密码、Cookie、Token、API Key、私钥、其他访问密钥和生产连接串；
- 是否确认输出只能用于技术学习，不用于人员处分、法律责任或绩效裁决。

四项没有全部确认时，不进入审查。

## 2. 当前状态

- 服务是否已经恢复；
- 是否仍有用户、数据或业务风险；
- 恢复时间无法确定时写 `unknown`。

仍在进行的事故只能进入 `active_handoff`，不能运行完整复盘。

## 3. 影响

- 受影响对象与可见症状；
- 范围和持续时间；
- 业务影响和数据影响；
- 不确定数字必须标记为 `unknown` 或范围值。

## 4. 时间线

至少覆盖：首次异常、系统或人员发现、关键处置、影响受控或恢复。每个节点分别写事件、当时观察、动作、结果和证据引用，不能把时间先后直接写成因果。

## 5. 证据

至少提供以下一类的脱敏摘要：指标、日志、调用链、发布/变更、工单或沟通记录。每条证据使用匿名引用 ID；原始敏感附件保留在组织授权系统内，不复制到本仓库。

## 6. 系统背景与临时动作

- 关键服务、依赖、责任角色和历史同类事件；
- 回滚、限流、降级、重启或热修，以及动作后的可观察结果；
- 不需要提供可直接操作生产环境的命令或凭据。

## 7. 已有复盘结论

可以提供现有根因候选和整改项；没有则明确写 `未提供`。不要为了让模板完整而补写负责人、日期或证据。

## 最小可接入标准

一份可计入 Stage 5C 的完整复盘案例必须同时满足：授权与脱敏四项确认、事故稳定、至少四个时间线节点、至少一类可核对证据、系统背景、临时动作结果，以及已有结论或“未提供”声明。
