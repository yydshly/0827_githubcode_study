# 阶段 0 前置结构假设

> 本文件只依据出版社公开目录建立导航假设，不是 `BOOK_OVERVIEW.md`，不得作为整书结论或原文证据。

## 结构判断

全书 22 章和两个附录可以初步分成五个编辑单元：

| 单元 | 章节范围 | 研究关注点 |
| --- | --- | --- |
| 价值观与职业选择 | 1–6 | 技术态度、长期主义、竞争力、成长困境 |
| 个人修炼 | 7–9、15 | 能力地图、学习、沟通、时间管理 |
| 编程与架构 | 10–14 | 编程本质、代码、范式、设计原则、分布式架构 |
| 研发与组织 | 16–22 | 效率、领导力、管理、绩效、招聘、文化、远程协作 |
| 人物与精神背景 | 附录 A–B | 工匠精神、创业经历、观点形成语境 |

这意味着阶段 0 不能只按章节逐章摘要。需要寻找贯穿五个单元的上位命题，并区分：

- 作者的方法论；
- 作者的价值判断；
- 技术知识说明；
- 编辑者提供的人物背景；
- 会随时代失效的具体技术建议。

## 待验证的上位命题

以下是研究假设，不是已通过三重验证的结论：

1. 程序员竞争力来自基础能力、工程质量、解决真实问题和持续学习的组合，而不是技术名词数量。
2. 技术选择应服务长期收益、系统完备性和维护成本，而不是短期潮流。
3. 软件质量问题经常与组织分工、管理方式和激励机制相互作用。
4. 技术领导力建立在吃透基础、建立标准、做正确的事和帮助团队成长之上。
5. 职业自由来自可迁移能力、经历积累和选择权，而不是单一职位等级。

## 本书对 cangjie-skill 的特殊压力点

### V1 可能被“合集结构”误导

同一个观点在多个章节出现，可能因为编辑时从不同文章选入，也可能只是措辞重复。验证时必须定位具体上下文、问题对象和推导结果，不能按关键词计数。

### V2 容易把普通知识包装成外推

例如设计原则本身已经是行业共识。需要检验陈皓提供的独特排序、组合或判停条件，而不是把 SOLID、DRY 等概念重新命名为新 Skill。

### V3 需要与模型常识做时间切片

今天模型熟知的工程原则，在文章写作时可能具有差异性。实验应分别记录“作者独特性”和“当前模型增量价值”，两者不能混为一项。

### 技术观点需要外部验证层

书内多处佐证只能证明观点稳定，不能证明观点在 2026 年仍然正确。架构、AI、远程协作等内容需要标注写作时间，并用当前权威资料做外部核验。
