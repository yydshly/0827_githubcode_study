# AIComicBuilder 必要信息总结

## 1. 核心能力

AIComicBuilder 实现的是“剧本到漫剧视频”的生产流程，而不是一个新的文生视频算法：

1. 接收创意、剧本或 TXT/DOCX/PDF。
2. 调用文本模型或 Agent 生成大纲、解析剧本、拆分分集、提取角色。
3. 调用图像模型生成角色参考图和镜头首尾帧。
4. 把剧本拆成场景、镜头、对白、动作、构图和视频提示词。
5. 调用视频模型逐镜生成短视频。
6. 使用 FFmpeg 完成排序、转场、字幕、BGM、片头片尾和合片。

小说可以作为上游入口，但需要经过章节选择、剧情压缩、分集和剧本化，不能把“小说输入”误解为整本原文一键得到稳定成片。

## 2. AIComicBuilder 与 Agent 的关系

推荐关系不是“Agent 替代工作台”，而是“工作台指挥 Agent 执行智能节点”：

```text
AIComicBuilder：决定下一步、准备上下文、创建任务
       ↓
Agent：完成改编、分析、规划、分镜、提示词或质检
       ↓
生成模型：生成文字、图片、视频或声音
       ↓
AIComicBuilder：保存结果、更新状态、展示审核、触发下一步或返工
```

库内部已经具备任务表、后台 Worker、流水线处理器和“一键续跑”，不强制依赖外部 Agent。外部 Agent 是可插拔增强：项目可以按大纲、剧本生成、剧本解析、角色提取、分镜、关键帧提示词、视频提示词等类别绑定百炼、Dify 或 Coze Agent。

另一种模式是由我们的总控 Agent 调用 AIComicBuilder API，但第一阶段更稳妥的架构是：**AIComicBuilder 保持确定性流程骨架，Agent 负责需要判断的节点。**

## 3. 为什么需要工作台

如果只是生成一段视频，直接调用工具即可。工作台的意义出现在长链路、多镜头和反复返修时：

- 统一保存项目、分集、角色、关系、场景、分镜和对白。
- `shot_assets` 记录首帧、尾帧、参考图和视频，并保留版本与当前激活状态。
- 任务队列记录等待、运行、完成、失败和重试。
- 某个镜头失败时只返修该镜头及必要下游，不必整集重做。
- 人工可以在剧本、角色、分镜、看板和预览页面检查中间结果。

因此它更像短剧生产的 MES/制片系统：Agent 是创作和判断岗位，模型是生成设备，AIComicBuilder 是生产控制层与项目真相源。

## 4. 技术原理

- 应用：Next.js 16、React 19、Zustand。
- 数据：SQLite + Drizzle ORM。
- 执行：数据库任务队列，Worker 轮询并调用不同 pipeline handler。
- 文本：OpenAI 兼容接口、Gemini；可绑定百炼/Dify/Coze Agent。
- 图像：OpenAI 兼容接口、Gemini、Kling、DashScope。
- 视频：Seedance、Kling、Veo、Wan、UCloud Seedance。
- 后处理：本地 FFmpeg。

主要流水线处理器包括 `script_outline`、`script_parse`、`character_extract`、`character_image`、`shot_split`、`frame_generate`、`video_generate` 和 `video_assemble`。

## 5. 已知边界

- 没有完整的小说 IP 改编、版权、审稿和内容运营体系。
- 当前主流水线没有成熟的角色 TTS、情绪配音和口型闭环。
- 连续性和视频质量检查异常时存在 fail-open 行为，不能直接作为严格质检门禁。
- 最终质量取决于外部模型、角色参考图、提示词和人工返修。
- 需要额外建设成本记录、模型路由、审核权限和发布流程，才能成为稳定生产系统。

## 6. 与 shuohao-skills / H3 类能力的差异

| 维度 | AIComicBuilder | shuohao-skills / H3 类能力 |
|---|---|---|
| 定位 | 有 UI、数据库和任务状态的生产工作台 | Agent 可调用的技能、脚本或单项生成能力 |
| 驱动方式 | 按业务流程创建任务并调用 Agent/模型 | 按一次请求执行一个能力或模板流程 |
| 强项 | 多集管理、版本、审核、返修、合片 | 快速、灵活、易组合，适合样片与单次任务 |
| 关系 | 控制层和项目真相源 | 可作为工作台中的执行节点 |

## 7. 最终决策

研究归档，不继续扩展。重新启动研究的条件：

1. 我们决定正式制作小说短剧或连续漫剧。
2. 单次 Agent 流程因多集、多角色、版本和返修出现管理瓶颈。
3. 需要让编剧、导演、审核和生成环节在同一工作台协作。

届时优先验证三件事：我们的小说改编 Agent 接口、TTS/口型链路、严格质检与成本路由。
